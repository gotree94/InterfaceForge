# ICD (Interface Control Document) 자동 생성 시스템 구상

> **드론(UAV) 사례 중심** — 11개 장비, 20개 메시지, 12개 버스, YAML 입력 → ROS2 .msg 자동 생성

---

## 1. ICD란 무엇인가

### 정의

ICD는 시스템 내 모든 전기적/데이터 인터페이스를 정의하는 **단일 규격 문서**입니다.

전통적인 항공/국방 분야에서는 수백 페이지 PDF로 관리되지만, 현대 ROS2 개발에서는:

- **SSOT (Single Source of Truth)**: YAML 파일 하나가 모든 인터페이스 정의
- **자동 생성 대상**: ROS2 .msg, DDS IDL, 문서, 테스트 코드
- **버전 관리**: Git으로 ICD 변경 이력 추적

### 장비 vs 메시지 vs 버스

```
Equipment ──송신──► Message ──전송──► Bus ──수신──► Equipment

  FC ─────────────────► ControlCmd ────────────────► ESC1
  FC ─────────────────► ControlCmd ────────────────► ESC2
  FC ─────────────────► ControlCmd ────────────────► ESC3
  FC ─────────────────► ControlCmd ────────────────► ESC4
  GPS ────────────────► GPSPosVel ─────────────────► FC
  LiDAR ──────────────► LiDARScan ─────────────────► Companion
```

### 4.2 계산 엔진

**Bus Utilization 계산**:

```
CAN_HIGH (1 Mbps):
  ControlCmd:  16 bytes × 8 (bit/byte) / 1,000,000 (bit/s) × 200 Hz = 2.56%
  ESCStatus1:   4 bytes × 8 / 1,000,000 × 50 Hz = 0.16%
  ESCStatus2:   4 bytes × 8 / 1,000,000 × 50 Hz = 0.16%
  ESCStatus3:   4 bytes × 8 / 1,000,000 × 50 Hz = 0.16%
  ESCStatus4:   4 bytes × 8 / 1,000,000 × 50 Hz = 0.16%
  CAN FD overhead (32 bit CRC + stuff bits + framing) ≈ 30%
  ───────────────────────────────────────────────────────
  Total utilization ≈ (2.56 + 0.16×4) × 1.3 ≈ 4.16%
  ✅ 여유 있음 (CAN FD 최대 권장 60%)
```

**CPU Load 추정 (FC, STM32F7 @ 216 MHz)**:

```
Task                    주기    실행시간 추정    CPU 점유율
─────────────────────────────────────────────────────────
센서 수집 (IMU)         1 ms     50 μs            5.0%
센서 수집 (GPS)        200 ms   200 μs            0.1%
센서 수집 (Baro)        50 ms   100 μs            0.2%
자세 제어 (Attitude)    5 ms    150 μs            3.0%
위치 제어 (Position)   20 ms    100 μs            0.5%
MAVLink 송수신          5 ms     80 μs            1.6%
CAN 송수신              5 ms    100 μs            2.0%
EKF 업데이트            5 ms    300 μs            6.0%
SD 로깅                100 ms   500 μs            0.5%
Safety 체크            10 ms     50 μs            0.5%
─────────────────────────────────────────────────────────
총 CPU 점유율 ≈ 19.4% ✅ 여유 있음
```

**WCRT (Worst-Case Response Time) 분석 (CAN_HIGH)**:

```
ControlCmd (ID=0x100, 우선순위最高):
  Transmission time: 16 bytes → ~13 bytes CAN FD (64 bit data + 32 bit CRC) ≈ 13 μs
  Blocking time (lowest priority message): 4 bytes ESCStatus → ~55 μs
  WCRT = 0 + 13 + 55 = 68 μs ✅ (deadline 5 ms)
```

## 5. 실행 예: 이륙 → Waypoint 비행 → 장애물 회피 → 복귀

### 5.1 시나리오 메시지 흐름

```
[Phase 1: 이륙]
CC ──MissionCmd{mode: 1 GOTO, alt: 10m}──► FC
FC ──Telemetry{alt: 0→10m, armed: true}──► CC
FC ──ControlCmd{thrust: 1500→1800}──► ESC1~4     # 증가 추력
LiDAR ──LiDARScan{ranges: [...]}──► CC            # 장애물 감지 시작

[Phase 2: Waypoint 비행]
CC ──WaypointList{count: 3, [wp1, wp2, wp3]}──► FC
GPS ──GPSPosVel{lat, lon, alt, speed}──► FC      # 5 Hz 갱신
FC ──ControlCmd{motor1~4: varying}──► ESC1~4     # 200 Hz 자세 제어
FC ──Telemetry{roll, pitch, yaw, pos}──► CC       # 100 Hz 상태 보고

[Phase 3: 장애물 회피]
LiDAR ──LiDARScan{ranges: front < 2m}──► CC
CC ──MissionCmd{mode: 1 GOTO, new waypoint}──► FC  # 회피 경로 재설정
FC ──ControlCmd{urgent attitude change}──► ESC1~4

[Phase 4: 복귀]
CC ──MissionCmd{mode: 3 RTL}──► FC
FC 자동 복귀 (home position)
FC ──ControlCmd{thrust: 1800→1200}──► ESC1~4    # 감속 하강
FC ──Telemetry{alt: 10→0m}──► CC
```

### 5.2 주요 메시지 Rate 요약

```
200 Hz ─── ControlCmd (FC → ESC, CAN FD)
100 Hz ─── Telemetry (FC → CC, USB), ViconPose (VICON → CC, ETH)
 50 Hz ─── GimbalAngle (CC → CAM, USB), ESCStatus (ESC → FC, CAN)
 10 Hz ─── LiDARScan (LiDAR → CC, USB), MissionCmd (CC → FC, USB)
  5 Hz ─── GPSPosVel (GPS → FC, UART)
  1 Hz ─── BatteryStatus (BATT → FC, I2C), SystemHealth (FC → CC, USB)
```

### 7.2 Isaac Sim 연동

Isaac Sim에서는 실제 CAN 하드웨어 대신 ROS2 토픽으로 추상화:

```
실제 하드웨어:    FC ──CAN FD──► ESC1~4
Isaac Sim:       ROS2 Topic (ControlCmd.msg) ──► IsaacSimHardwarePlugin
```

→ **같은 ROS2 메시지**를 사용하므로 Sim↔Real 전환 비용이 0에 가까움

### 7.3 Sim-to-Real 차이 보정

| 항목 | Sim 기본값 | Real 보정 | calibration.yaml |
|---|---|---|---|
| 모터 응답 지연 | 0 ms | 5-10 ms (PWM+ESC) | motor_delay_ms: 8 |
| 추력 계수 | 이상적 | 85-95% | thrust_factor: 0.9 |
| drag 계수 | 0 | 실제 공기 저항 | drag_coefficient: 0.02 |
| 센서 노이즈 | 0 | IMU random walk | imu_gyro_noise_density: 0.005 |
